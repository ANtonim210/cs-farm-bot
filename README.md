# Telegram File Gate Bot

Telegram-бот выдаёт файлы по персональным deep-link ссылкам и проверяет подписку на обязательные каналы.

**Файлы не скачиваются на Render.** Администратор отправляет файл в личный чат с ботом, приложение сохраняет только `source_chat_id` и `message_id` в PostgreSQL. При выдаче бот вызывает Telegram `copyMessage`, то есть Telegram копирует уже существующее сообщение на своей стороне.

## Важно о больших файлах

Для файлов, которые администратор может отправить боту в Telegram, бот не загружает байты файла на Render и не использует `getFile`. Обработка 4-ГБ медиа зависит от того, как Telegram принимает такое медиа и разрешает его копирование Bot API; перед массовым использованием обязательно проверь конкретный файл. В официальной документации Bot API заявлена повторная отправка уже существующего Telegram-файла по `file_id` без повторной загрузки, а `copyMessage` копирует сообщение на стороне Telegram. Сам бот должен быть актуальным и обрабатывать большие значения `file_size`.

Технически бот всё равно использует Telegram Bot API для команд, проверки подписок и `copyMessage`. Но он **не скачивает и не загружает файл заново**, и стороннее файловое хранилище не используется.

## Что умеет

- `/start` — приветствие или получение файла по ссылке `https://t.me/BOT_USERNAME?start=TOKEN`.
- `/admin` — панель администратора.
- Добавление набора из одного или двух файлов: после первого файла бот спрашивает, нужен ли второй.
- Если админ выбирает «Добавить второй файл», он отправляет второе сообщение с файлом; если «Готово, только один файл» — ссылка создаётся сразу.
- Одна уникальная ссылка выдаёт оба файла по очереди (или только первый, если второго нет).
- Список файлов и число выдач.
- Удаление файла по его ID.
- Добавление обязательного канала (`@username` или `-100...`) и ссылки для вступления.
- Удаление канала через `/delchannel CHAT_ID`.
- `/cancel` — отмена текущего действия.
- `/health` — health endpoint для Render и UptimeRobot.

## Перед запуском

1. Создай бота через `@BotFather` и скопируй токен.
2. Узнай свой Telegram user ID и укажи его в `ADMIN_IDS`.
3. Создай бесплатную PostgreSQL базу, например в Neon, и скопируй её connection string.
4. При добавлении обязательного канала добавь бота администратором канала. Иначе `getChatMember` не сможет надёжно проверить подписчиков.

## GitHub

Загрузи все файлы проекта в новый GitHub-репозиторий. Не загружай токен или `.env`.

## Render

Создай **New + → Web Service**, подключи репозиторий и укажи:

- Runtime: Python 3
- Build command: `pip install -r requirements.txt`
- Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
- Plan: Free

Добавь Environment Variables:

| Variable | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `ADMIN_IDS` | твой числовой Telegram ID; несколько ID через запятую |
| `DATABASE_URL` | connection string PostgreSQL (Neon) |
| `WEBHOOK_SECRET` | случайная строка 32+ символов |
| `WEBHOOK_URL` | полный URL Render, например `https://telegram-file-gate.onrender.com` без `/` в конце |

Можно вместо ручной настройки использовать `render.yaml`, но секреты всё равно нужно заполнить в Render Dashboard.

## UptimeRobot

Создай монитор **HTTP(s)** на URL:

`https://YOUR-SERVICE.onrender.com/health`

Интервал — 5 минут (если такой интервал доступен в твоём плане). Успешный ответ выглядит так:

```json
{"status":"ok","database":"ok"}
```

Пинг помогает не допускать простоя из-за отсутствия запросов, но бесплатный Render не гарантирует 100% uptime и может перезапускать сервис.

## Добавление файла

1. Напиши боту `/admin`.
2. Нажми «Добавить файл».
3. Отправь первый файл боту отдельным сообщением.
4. Бот спросит, нужен ли второй файл для этой же ссылки.
5. Нажми «Добавить второй файл» и отправь его, либо нажми «Готово, только один файл».
6. Бот пришлёт одну персональную ссылку на весь набор. Получатель получит файлы в том же порядке.

Файл должен оставаться в исходном чате с ботом. Если удалить исходное сообщение, ссылка перестанет работать.
